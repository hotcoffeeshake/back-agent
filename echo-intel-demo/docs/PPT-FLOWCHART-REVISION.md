## 3. 共同改动 —— P1–P4 每页都加「Manager 房间」层

**现状问题**：四页都画成"客户直接进客户服务 Team、Leader 直接接管"。真实机制是：需求一律先到 **Manager 房间**，由 Manager 被动调度对应 Team 的 Leader，Leader 产出（澄清追问/方案报告）也回 Manager 房间再转达客户。

**每页统一做法（P1/P2/P3/P4 各做一遍）：**

1. 在「客户侧」与「企业内部 · 回声智能客户服务 Team」之间，新增 1 个框：
   - 框名：`Manager 房间`
   - 副标：`统一需求入口 · 被动调度`
2. 新增两条连线：
   - 客户侧 → Manager 房间 → Team Leader，标注 `需求`
   - Team Leader → Manager 房间 → 客户侧，标注 `澄清追问 / 方案报告`
3. 连线样式沿用页内现有实线/虚线规则（任务流实线、消息返回虚线或按原图例）。

## 4. P1（第 12 页 · 闭环 1）具体改法

**现状问题**：需求诊断「提取已有条件→补齐关键缺口」→ 方案生成，单向直通，没有"问用户"环节；真实机制是需求不清晰必须暂停追问、不许猜。

1. 在「需求诊断」Worker 卡片下方新增**判定节点**：
   - 文字：`关键字段缺失 / 置信度 < 0.7 → CLARIFYING`
2. 从判定节点向 Manager 房间拉一条**实线**，标注：
   - `CLARIFYING_REPORT（第 1/3 轮 · 最多 2 个问题）`
3. 从 Manager 房间回需求诊断拉一条**虚线**，标注：
   - `客户补充回答 → 重新派发（合并澄清历史）`
4. 判定节点旁加小字注释：
   - `循环上限 3 轮；超出 → 生成接管包转人工（闭环 3）`
5. 在「需求诊断 → 方案生成」的连线上加标注：
   - `status=READY`

## 5. P2（第 13 页 · 闭环 2）具体改法

**现状问题**：方案生成 Worker 直接连到「锁设备档期/锁飞手档期/创建订单」三个 Business System，像 Agent 自己在操作业务系统。真实机制是控制平面分离：Agent 不碰业务系统，只经工具网关调用、全程带令牌。

1. **连线改经网关**：新增 1 个框 `MCP 工具网关`，放在 Worker 与 Business System 之间；Worker 的锁档/建单调用（对应 `hold_inventory` / `create_order_draft`）改为经网关再到业务系统。
2. **令牌流转标注**：在「Policy & Approval」与「MCP Gateway」之间标注：
   - `签发 confirmation_token`
   - 网关处标注：`验签 · 无有效令牌 100% 阻断`
3. **边界注释**：三个 Business System 区域上方加一行小字：
   - `Agent 只持有状态引用；状态 / 审批 / 幂等由控制平面持有`
4. **全链路字段**：保留现有 `Idempotency-Key · state_version · trace_id` 标注，在末尾追加 `confirmation_token`。
5. 失败补偿（release_hold → 人工恢复队列）已有，保留不动。

## 7. P4（第 15 页 · 闭环 4）具体改法

**现状问题**：①Team 命名错（"商户运营 Team + 客服运营 Team + 平台知识控制面"，真实只有两支 Team）；②Worker 卡片不全（只有 资料管理、质检分析，缺 3 类）。

1. **Team 命名替换**：顶部横幅改为：
   - 原文：`企业内部 · 商户运营 Team + 客服运营 Team + 平台知识控制面`
   - 改为：`企业内部 · 客户服务 Team + 平台运营 Team + 平台知识控制面`

2. **新增 3 个 Worker 卡片**（样式与现有 Worker 卡一致）：
   - `文档解析`：`解析商户文档 / 表格 / 图片 → 知识候选`（放在"商户资料"双入口分支下）

## 8. 技术要点（python-pptx 执行提示）

- 新增文本框：`slide.shapes.add_textbox(left, top, width, height)`，`text_frame.word_wrap = True`。
- 字体：每个新增/改动的 run 显式设置 `run.font.name = "微软雅黑"`（中文场景下建议同时设置 `run.font.name` 的东亚字体名，或直接用 `run.font.name = "Microsoft YaHei"`）；注释字号 9–10pt、颜色 `RGBColor(0x59,0x59,0x59)`。
- 替换文字时**保格式**：全文写入第一个 run、清空其余 run（不要对 `text_frame.text` 整体赋值，会丢字体）。
- 新增框/线若与页面图形相交，可微移位置，但不得改变页面整体版式。
- 连线（连接符/箭头）尽量复用页面现有连接符样式；若 python-pptx 难以精确画线，允许在 PPT 中人工补画，但必须与指令中的端点、标注一致。
