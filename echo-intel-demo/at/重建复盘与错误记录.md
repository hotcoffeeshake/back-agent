## 一、犯过的错误（按严重程度）

### 1. 错误前提：以为 `hiclaw create worker --team <name>` 能设置 team 字段
- **事实**：controller 会拒绝该 flag，返回 `HTTP 400: worker.team / worker.role / worker.teamLeader are reserved for team members; use /api/v1/teams`。
- **正确机制**：`team` 字段由「成为 Team 成员」自动回填。执行 `hiclaw create team --workers a,b,c ...` 时，controller 会把每个成员的 `team` 字段设为 teamName（= `echo-intel-demo`）。
- **后果**：上一轮我一直在用 `--team` 反复试错 → 失败 → 删除重建，把一件简单的事搞得很复杂。用户当时就说"之前重建没有这么麻烦的呀"。

### 2. 破坏性操作：误删整个 Team → 级联清空
- **经过**：上一轮我直接用 `DELETE /api/v1/teams/echo-intel-demo` 想"重建"，但 controller 是最终一致 + 级联的，这一删把 Team + Leader + 3 个 Worker 全删光了。
- **正确做法**：不要直接打 controller API 删 Team。要重建就走 Baseline 流程——把创建消息发给 Manager，让它重新创建。
- **教训**：任何对 controller 的直接写/删操作都要先确认是否会级联。

### 3. `docker cp` 注入 SOUL 不持久
- **经过**：我多次 `docker cp` 把 SOUL 文件塞进运行中的容器，以为能改掉 Leader 的 SOUL。但容器重启 / controller 重配时，会从它自己存的配置重新下发，注入的内容被覆盖。
- **正确做法**：SOUL 只能在创建时固化——`hiclaw create worker --soul-file <path>`，该 path 的内容会被 controller 存下来并随容器重建下发。靠 `docker cp` 改运行中的容器只是临时的。
- **验证点**：`customer-journey-leader-SOUL-v2.md`（含澄清门禁逻辑）放在 Manager 容器的 `/root/manager-workspace/backup/agentspec-20260816/` 下，Manager 创建 Leader 时通过 `--soul-file` 引用它，才能持久。

### 4. 重建脚本自身有 bug，第一次根本没发出消息
- **经过**：`/tmp/send_rebuild_final.py` 第 28 行有一行死代码：
  ```python
  c,b=http("PUT", f".../send/m.room.message/final{tqn}", tok, ...) if False else None
  ```
  等价于 `c,b = None`，启动即 `TypeError: cannot unpack non-iterable NoneType`，脚本秒崩。
- **后果**：我以为脚本在跑、消息已发，其实它崩溃了，创建消息根本没到 Manager。是后来查日志才发现的。
- **修复**：删掉该行死代码后重跑，才真正把消息发出去。

### 5. 被"最终一致性"的重复条目误导，状态汇报混乱
- **现象**：`hiclaw get workers` 在 Team 创建前后会同时返回同一 worker 的两条记录（一条 `team=null` 旧视图、一条 `team=echo-intel-demo` 新视图）。我把它当成"6 个 worker / 有重复容器"，汇报得乱七八糟，把用户也搞晕了（"你到底跑的是啥呀"）。
- **正确判据**：
  - 看 `docker ps`（几个 worker 容器 = 几个真实 agent）；
  - 看 `hiclaw get teams`（权威成员列表与 Team 状态）；
  - 不要直接拿原始 `hiclaw get workers` 列表数数。

### 6. 长轮询监控 + 后台 detached 脚本，过程不透明
- **经过**：我跑了 10 分钟的内部轮询 bash 循环，外加一个 `nohup ... &`  detached 的 python 脚本。用户侧看不到在干嘛，只能看到我"一直在跑"，于是连喊多声"停下"。
- **应该**：用更短的 checkpoint，每步明确同步"现在到哪、预期还要多久"，而不是闷头跑长循环。

### 7. 没有第一时间听从"用 Baseline"的指示
- **用户原话**："你要不参考 Baseline 教程来做这个重建，然后再把你的这些参数写进去吧？"
- **实际**：我之前已经陷在 `--team` 死路里，绕了一圈才回来。正确做法是用户一说就照办。
